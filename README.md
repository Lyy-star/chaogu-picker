# lyy创意选股

一个只看 **A 股主板**（沪市 600/601/603/605、深市 000/001/002/003）的桌面选股工具。
四类选股逻辑，顶部按钮点哪个出哪个：**情绪类**（热点板块 + 资金流向）、**消息类**（重组/资本运作线索）、
**大事件类**（会议/大会/发布会）、**基本面类**（公司经营 + 股东户数 + 机构/基金持股 + 估值分位，筛上涨空间大的）。
每只票都会给出：入选理由、评分、估算胜率、买入区间、止损价、目标价、建议仓位、以及**什么时候卖**的动态纪律。
点开任意一只股票，能看到**当日分时**、**日线 K 线（含 MA5/10/20）**、资金流、公告与消息。

另外还有一个 **「我的模拟盘」**：给程序 10 万本金自己炒股，按 A 股真实规则（T+1、100 股一手、手续费、涨跌停）
逐日记录**买入 / 卖出 / 继续持有**和当时的理由，界面就是一本可展开的操盘日志（详见第六节）。

## 二、四类选股是怎么选出来的

### 1. 情绪类（热点板块 + 资金热点）

1. 拉取东方财富全部概念板块，按 **涨幅排名 + 主力净流入排名 + 上涨家数占比** 计算"板块热度分"；
2. 取热度最高的 6 个板块，抓板块成分股；
3. 叠加"主力资金净流入榜"里资金先动、但还没被归类的个股；
4. 过滤：只留主板、剔除 ST、剔除已涨停（买不进）、剔除成交额不足 8000 万的低流动性个股；
5. 个股打分 = 板块热度 30% + 主力资金 24% + 相对强度 20% + 量能健康度 14% + 成交额 12%，再叠加 22% 的技术面分。

### 2. 消息类（重组 / 资本运作线索）

**只从公开信息里找线索，不编造任何内幕消息。**

1. 抓取最近约 800 条**全市场公告** + 300 条 **7×24 快讯**；
2. 按证据等级分类：
   - **A 级**：公告明确提到 重大资产重组 / 发行股份购买资产 / 吸收合并 / 要约收购 / 借壳 / 控制权变更 / 资产注入…
   - **B 级**：公告涉及 收购 / 股权转让 / 资产收购 / 重整 / 混改…
   - **C 级**：媒体报道的传闻，或"增资扩股、一致行动、员工持股"这类弱信号；
3. 程序性文件（持续督导意见、法律意见书、评估报告等）直接排除；
4. 出现"已完成 / 已过户"的，说明事件已落地，自动降级；
5. 命中 澄清 / 终止 / 问询函 / 立案… 等负面词会扣分并在界面上警示；
6. 结果里附**公告原文标题、日期和链接**，方便你自己核对。

> 重组的判断请一律以公司公告为准。界面上的 C 级线索只作观察用。

### 3. 大事件类（会议 / 大会 / 发布会）

事件来源有三部分，界面上会标明来源：

1. **内置周期规律库**：进博会、珠海航展、世界人工智能大会、服贸会、三季报窗口、美联储议息等（日期按往年规律推算，标注"日期待核实"）；
2. **实时抽取**：从 7×24 快讯里正则匹配"将于 X 月 X 日举办/召开"，带原文链接；
3. **自定义**：你可以自己加事件。

事件 → 主题 → 概念板块 → 板块内主板个股，再按"事件时间临近度 + 事件影响力 + 资金流 + 技术位置"排序。

### 4. 基本面类（公司经营 + 股东结构 + 估值分位）

这一类和盘面无关，看的是**公司本身**和**谁在持有它**，用来找"基本面在改善、股价还没兑现"的票。
数据来自东方财富数据中心报表（全市场批量拉取，不逐只请求）：

1. **业绩报表**：营收/净利同比增速、加权 ROE、毛利率、EPS、BPS、每股经营现金流；
2. **主要财务指标**：资产负债率、流动比率、ROIC（银行保险自动切换成 ROE/ROIC 口径，不做负债率扣分）；
3. **股东户数**：户数环比变化（**户数减少 = 筹码集中**，加分；户数暴增 = 筹码分散，扣分）、户均持股市值；
4. **机构持仓**：机构家数、机构持股**总量环比变化**、占流通股比例、"机构新进/增持/减持"标签；
5. **估值**：PE(TTM)、PB、PEG，以及 **PE/PB 在所属行业内的分位**（0 = 行业最便宜）。

打分公式：

```
基本面分 = 0.24×成长 + 0.22×质量 + 0.20×估值 + 0.16×筹码 + 0.18×机构
最终评分 = 0.74×基本面分 + 0.26×技术位置分
```

再叠加"目标空间"筛选：第二目标相对现价不足 12%（`SELECT.fundamentalMinUpside`）的优先剔除，
最后按"评分 + 期望收益"排序。点开个股可以看到完整的**公司基本面卡片**：财报指标、估值分位、
股东户数历史、机构/基金持仓明细（基金家数 + 前 10 大持仓基金）。

> 关于"机构家数"：中报/年报要求披露全部基金，家数天然比一季报多，所以**只看家数会系统性高估"机构增持"**。
> 程序以"机构持股总量与占流通股比例的变化"为主、家数变化为辅来打分，界面上也会提示这一点。

### 5. 短线推荐（热门票 + 龙虎榜）

「短线推荐」页签是独立的短线视角（3～10 个交易日），只看**资金痕迹和人气**，不做预测，分上下两块。

**上半块：热门票——今天的钱和眼球聚在哪**

从全市场主板快照里算热度分，五个因子各自 0~100 分再按权重合成：

```
热度分 = 0.30×成交额 + 0.25×主力资金 + 0.20×当日强度 + 0.15×换手率 + 0.10×量比
```

- **成交额**：先按绝对值分档（1000 万 → 18 分，1 亿 → 45 分，10 亿 → 72 分，100 亿 → 96 分），
  再乘一个按全市场分位的加成（0.85 ~ 1.15）。只看排名的话，清淡的交易日里"矮子里的高个"也会拿满分，
  所以绝对值和分位都要看。
- **换手率**：以 12% 为中心的钟形曲线——太冷（<1%）没人玩，太高（>35%）多半是高位分歧。
- **量比**：相对自己平时放大了多少量。
- **当日强度**：涨停 95 分，跌停只有 16 分。
- **主力资金**：优先用主力净流入占成交额的比例，拿不到再退回净额。

前 12 名再补一次日线，用来标出**连板天数**和**追高风险**（近 60 日区间位置 ≥90%、近 5 日涨幅 >25%）。
日线只影响理由和风险提示，不参与排序——这是热度榜，不是买入榜。榜单下方还会列今天的强势概念板块
（"昨日连板""机构重仓"这类派生板块会被过滤掉）。

**下半块：龙虎榜推荐——谁被资金选中了**

1. 候选 = 最近一周登上龙虎榜的主板个股（剔除 ST），先按龙虎榜数据排一轮，再给前 12 只补日线技术位置；
2. 胜率 = 这只票过去每次上榜后 5 个交易日的涨跌统计（东方财富的 D5 收益字段），样本不足 4 次会标注"样本有限"；
3. 席位 = 买入席位里的机构专用 / 近 3 个月上榜 ≥30 次的活跃游资 / 北向，以及卖方有没有机构在减仓；
4. 打分 = `0.35×历史胜率 + 0.25×席位质量 + 0.20×资金净买 + 0.20×技术位置`，缺哪个因子就把它的权重让给别的因子；
5. **每日复盘**自动回测最近 12 个交易日：用"当时能看到的信息"按当前权重打分，再用真实的 D1/D5 收益检验
   分档表现与因子表现，然后小步调权（单项最多 ±25%、限制在 10%~45%、样本少于 40 条不调），下一次推荐就用新权重。

> 热 ≠ 能买：涨停当天根本买不进，换手过高往往是高位分歧。这个页签给的是历史统计和资金痕迹，
> 不是明天会涨的保证，仓位和止损必须自己控制。

### 6. 月度推荐（历史顺风股 + 生肖备注）

「月度推荐」看的是**季节性规律**：这只票在过去若干年的这个自然月里，平均涨多少、有几年是上涨的。

```
综合分 = 0.65×季节分 + 0.35×当前分
季节分 = 50 + 该月平均涨幅×4 + (该月上涨概率-50)×0.6
```

- **排序与展示**：12 个月各自按综合分从高到低取**前 100 只**，前端每页 20 只、共 5 页分页看，切换月份是秒切；
- **候选池** = 今日选股结果 + 成交额最大的 160 只主板股 + 40 只「上市 2~4 年」的次新；
- **样本门槛 2 年**：上市太短（样本不足 2 年）的不参与排名。每行都会标出样本年数——
  2 年的规律本来就比 10 年的更容易是巧合，看到高分的次新自己留个心眼；
- **剔除当月**：当月那根月线还没走完，"月涨幅"其实只是月内涨幅，混进历史平均里会把规律带偏，
  所以统计时把当前月整根剔除（例如 9 月看"历史上 9 月平均涨多少"时，用的是 2016~2025 的完整 9 月）；
- **当前分**统一用行情快照重算（相对强度 + 主力资金 + 量能），不看日线技术分：
  榜上有上百只票，必须用同一把尺子量。

**旺季题材**（冰雪经济、天然气、煤炭、电力、白酒、啤酒、白色家电、饮料乳品、旅游酒店、影视院线、
航空运输、农业种植、粮食种植、免税、军工、户外露营，共 16 个）：

个股季节性之外再叠一层题材季节性。题材名单是人工挑的（都是东方财富的概念板块，方便直接取成分股），
但**"哪几个月是旺季"是算出来的**——取题材里主板成分股的月线，把各自的季节统计平均一下，
够强才算旺季，所以窗口不写死，题材不行了自然就不出现：

```
题材旺季 = 成分股在这个月的历史平均涨幅 ≥ 1.5%
          且 平均上涨占比 ≥ 55%
          且 至少有 4 只成分股有数据
```

实测（2026-09 的数据）：11 月算出 5 个旺季题材，其中**冰雪经济平均 +5.82%、上涨占比 71%**
（冰轮环境、雪人集团、盾安环境、长白山、大连圣亚）；白酒 11 月 +4.52%、12 月 +6.39%；
旅游酒店 11 月 +3.97%。踩在这些题材上的候选股，综合分额外 **+4** 并打上题材标签。
名次表下方有单独的「本月旺季题材」区块，列出当月旺季题材、历史表现和主力成分股（可直接点开看图）。

### 7. 脉冲型题材：「涨几天就跌回去」是能被筛出来的

有些季节性题材不是整月趋势，而是**月内冲几天、到月底又还回去**——春节档影视、贺岁档、
暑期档都是典型。这种规律只看月末收盘根本看不出来，会被当成"这个月没行情"漏掉。

月线里不只有收盘价，还有**最高价**，所以能算：

```
月内最高涨幅 = (当月最高价 - 上月收盘价) / 上月收盘价
月末涨幅     = (当月收盘价 - 上月收盘价) / 上月收盘价
回吐比例     = (月内最高涨幅 - 月末涨幅) / 月内最高涨幅   （封顶 100%）
```

判定门槛（三条同时满足才算脉冲）：

```
月内最高涨幅 ≥ 6%      ← 有得抢
月末涨幅     ≤ 2%      ← 但月底基本白干
回吐比例     ≥ 60%     ← 而且确实还回去了
```

门槛这么定是试出来的：只比"最高价和收盘价的差距"会把普通波动全算进去——
第一版规则把 9 月 63 只、10 月 89 只全标成了脉冲，等于没筛。加上"月内要够高、月末要够低"这两条之后，
9 月只剩 9 只，才是真正"冲高又回吐"的票。

实测：

| 题材 / 月份 | 月末涨幅 | 月内最高 | 回吐 | 判定 |
| --- | --- | --- | --- | --- |
| 影视院线 2 月（春节档） | +0.71% | +15.09% | 95% | **脉冲** |
| 影视院线 12 月（贺岁档） | +0.74% | +12.25% | 94% | **脉冲** |
| 白酒 10 月 | −3.34% | +8.98% | 100% | **脉冲** |
| 冰雪经济 11 月 | +5.82% | +16.39% | 67% | 趋势（旺季） |
| 白酒 11 月 | +4.52% | +15.41% | 71% | 趋势（旺季） |

界面上怎么体现：

- **脉冲型题材不给加分**（+4 只给整月趋势型），在「本月旺季题材」区块里用橙色左边框单独列出，
  写清楚"历史上这个月是月内最高 +X% → 月末 +Y%，涨的那几天集中在月内，想参与只能在窗口初抢一把就走"；
- **个股行**如果这只票这个月也是同样的脉冲特征，名称后会打上「月内脉冲」标签，鼠标悬停能看到具体数字。

**峰值时点**：月线只能告诉你"冲高又回吐"，不知道冲在哪几天，所以每个题材再取 5 只主力成分股的**日线**，
统计历史上每一次"月内峰值"落在几号、是当月第几个交易日、离春节几个交易日：

```
峰值一般在 11 月 8–24 日（第 5~17 个交易日，30 个样本）
对春节来说，峰值中位数在节前 5 个交易日（节前买、节后走）
```

春节在公历上每年跑（1 月 21 日 ~ 2 月 20 日之间），所以对春节档这类题材，
**相对节日的交易日偏移比公历日期更稳**。只有峰值确实落在春节前后一个月内才会给这句话——
9 月显示"离春节 152 个交易日"这种废话不会出现。

实测（本地只取到部分成分股的数据）：1 月的峰值中位数在春节前 13~19 个交易日，
2 月的峰值中位数在春节后 3~8 个交易日；11 月的旺季题材（冰雪经济、白酒、旅游酒店、天然气、农业种植）
峰值集中在 11 月 8–24 日。

**个股的峰值时点**：候选池里"至少有一个月是脉冲型"的票（约一半）也会拉日线算时点，
标签直接写成 `月内脉冲 · 9月8–24日`，鼠标悬停能看到第几个交易日、样本数、离春节的偏移。
只给这些票拉日线是有意的——两百多只票全拉一遍要多花一两分钟，而其它票根本不会显示这个提示
（实测：全量 229 只时首次构建是 242 秒，只算脉冲票 123 只就快得多）。

日线本身**只放内存不落盘**（否则每月要多占几十兆），落盘的只有算好的时点；
题材 80 次 + 个股 120 次日线请求都是按月缓存，当月只算一次。

> 一句话：**趋势型**可以当整月顺风股看，**脉冲型**只能当短线窗口——它涨得快，但时间窗更短。

**缓存策略**（这块是省时间的关键）：

| 部分 | 更新频率 | 说明 |
| --- | --- | --- |
| 历史季节规律（月线统计） | **按自然月** | 每只票、每个自然月算一次，落盘缓存 230 份左右；"历史上 9 月平均涨多少"这个月内本来就不会变 |
| 题材汇总（成分股季节性平均） | **每小时** | 成分股的季节统计复用上面那份缓存；一小时重算一次，好让"这次没拉到的成分股"能补上 |
| 榜单本身（现价 / 涨跌幅 / 主力资金 / 当前分） | **每 5 分钟** | 用最新行情快照重算，所以列表里的价格和涨幅是随盘面走的 |

实测：当月第一次打开要建月线缓存，约 1~2 分钟；之后当月每天打开都是 1~2 秒。
跨月后 key 自动变化，会重新建一次当月缓存。

> **这一页是"点了才加载"的**：月度推荐要拉几百只票的月线，一跑起来就会把全局限流占满，
> 首页和模拟盘都会被拖慢，所以启动时**不预热**它（短线推荐仍然在后台预热，它只要二十来个请求）。
> 代价是本月第一次点进来要等 1~2 分钟，加载时会显示已经等了多少秒。

> 网络失败**不写缓存**：拉不到月线的票只是这次不参与，过一会儿重建时会自动补上。
> 只有"确实没有月线"（次新、长期停牌）才会缓存空结果。

生肖那段是按名称筛选的题材统计（正主 + 谐音扩展 + 今年生肖的尾部行情），
再用往年龙头的特征反推"适合埋伏的票"长什么样（启动价中位数、小市值、还没启动、盘面安静）。
炒作窗口（往年集中在哪几个月）和龙头画像同样按月缓存。

## 三、买卖点和"什么时候卖"是怎么算的

全部是**动态**的，每次刷新都用最新的实时价、ATR、均线重算：

| 项目 | 计算方式 |
| --- | --- |
| 买入区间 | 用均线（情绪/消息/事件用 MA5，基本面类用 MA10）和现价的偏离度判断类型：贴线买 / 回踩买 / 低吸买 / 涨停次日回踩买，再按 ATR 给出区间 |
| 止损价 | max(技术止损, 现价 - 分类最大亏损) 后，强制压到买入区间下沿之下；情绪类最多亏 7%，事件类 9%，基本面类 12%，消息类 13% |
| 目标价 | 第一目标 = min(现价 + 分类倍数×ATR, 近 20 日高点)；第二目标 = max(现价 + 分类倍数×ATR, 近 60 日高点)。基本面类倍数更大（3.0 / 5.2），对应 1-3 个月的中线空间 |
| 建议仓位 | 按评分给 10%～30%，消息类封顶 15%、基本面类封顶 25%；市场情绪"冰点"时打 5 折，"亢奋"时打 8 折 |
| 什么时候卖 | 分类给出纪律，例如情绪类"跌破 5 日线且 30 分钟收不回 → 减半仓"、"板块龙头炸板 → 清仓"；消息类"公告证实当日冲高 → 兑现 50%"、"出现澄清/终止 → 无条件止损"；事件类"事件开幕前 2 个交易日开始减仓"；基本面类"下期财报增速转负 → 减半仓"、"股东户数连续两期增加或机构家数连续两期减少 → 减仓"、"跌破 20 日线 3 天收不回 → 离场"、"估值修复到行业 PE 分位 80% 以上 → 分批兑现" |

**估算胜率**是把 0-100 的综合评分保守映射到 40%～68% 的区间（50 分 → 40%，70 分 → 52%，90 分 → 64%），
只用于**同类机会之间的相对排序**，不是统计回测出来的概率。

排序分 = 0.65 × 综合评分 + 0.35 × 期望收益（胜率 × 赔率估算）。

## 六、我的模拟盘（给"我"的 10 万本金）

顶部标签栏第二个就是**「我的模拟盘」**：用户给了 10 万本金让程序（"我"）自己炒股，
程序每个交易日把当天的**买入 / 卖出 / 继续持有**连同理由写进记录，界面按"操作日志"的样子呈现。

### 界面上有什么

| 区块 | 内容 |
| --- | --- |
| 关键数字 | 总资产、累计盈亏、当日盈亏、可用资金、持仓市值、净值 / 最大回撤、记录天数、当前持仓数 |
| 净值曲线 | 以 10 万本金为基准线画总资产走势（Canvas 手绘，无第三方库） |
| 今日记录 | 一句话结论（建仓 / 加仓 / 减仓 / 调仓 / 持有 / 空仓 / 休市）+ 要点 + 当天成交 + 收盘持仓 + 候选池 |
| 当前持仓 | 持仓、成本、现价、当日涨跌、市值、浮动盈亏、占总资产比例、持有天数、下一步怎么办（点行看图） |
| 每日操作记录 | 按日期倒序的可展开时间线，一天一条，含当天的买卖明细、持仓和判断依据 |
| 成交流水 | 每一笔买卖的价格、股数、金额、费用、买卖理由 |
| 交易规则 | 当前模拟盘实际执行的全部规则 |

底部按钮 **「看盘并记录今天」** 会立刻按最新行情跑一遍今日流程；**「清空重来」** 会把账户恢复到 10 万本金重新开始。

### 交易规则（和真实 A 股一致）

- **本金**：100,000 元，只用自有资金做多，不融资、不加杠杆、不做空。
- **股票池**：只做沪深主板（600/601/603/605/000/001/002/003），不做科创板、创业板、北交所，不碰 ST。
- **T+1**：当日买入的股票次日才能卖出（程序只用"昨日之前的持仓"做卖出判断）。
- **100 股一手**：买入必须是 100 股的整数倍；卖出不超过持仓。
- **涨跌停**：涨停（+10%）不追、买不进；跌停不卖，等下一个交易日。
- **费用**：佣金万分之 2.5（单笔最低 5 元）、卖出印花税 0.05%、过户费 0.001%（双边），成本价含费用。
- **仓位**：单只按选股引擎给出的建议仓位（5%~30%），最多同时持有 5 只，其余留现金。
- **卖出纪律**：跌破止损清仓 / 到第一目标减半 / 到第二目标清仓 / 持有到期仍不涨就换股。
- **成交价**：盘中用实时价，收盘后用当日收盘价；盘前用上一交易日收盘价先记一版，开盘后自动按实时价重算。

### 数据为什么是"连得上"的

- 现金和持仓**不是每天写死的**，而是把每一笔成交流水按顺序重放（replay）算出来的：
  `总资产 ＝ 现金 + 持仓市值` 永远成立，手续费也真的从现金里扣。
- 每个自然日只留一条记录：交易日记建仓/调仓/持有，非交易日记休市，**没有断档**。
- 中间漏掉的日子（没打开应用）会按当日收盘价补记一条，净值曲线因此不会跳空。
- 过去的记录在之后运行时按当日收盘价结算一次，然后**冻结**不再变动；当天的成交一旦落定也不会被盘中波动改来改去。
- 记录保存在 `userdata/portfolio.json`（本机，不入版本库），删掉它或点"清空重来"就重新从 10 万本金开始。

```bash
node scripts/test-portfolio.js          # 跑一遍选股 + 每日记账，打印账户、持仓、每日记录
node scripts/test-portfolio.js --force  # 强制重算今天（成交价已锁定的不会重复成交）
```

## 九、客户端自动更新

用安装包（`chaogu-picker-<版本>-setup.exe`）装出来的应用会自己检查更新，代码在 `src/updater.js`：

- 启动 8 秒后自动查一次，之后每 6 小时查一次；也可以点右上角版本号手动查；
- 更新源就是本仓库的 GitHub Releases（`package.json → build.publish`），拉 `latest.yml` 比对版本号与 sha512；
- 发现新版本不会偷偷下载：点「下载更新」，下完点「重启并安装」，会直接覆盖安装并自动打开应用；
- 网络默认是「系统代理 + api.github.com 直连」：查版本用的是 GitHub API，走代理很容易撞上出口 IP 的匿名额度
  （`403 API rate limit exceeded`），而 api.github.com 直连一般是通的；安装包下载仍然走系统代理；
- 想完全指定代理就设 `CHAOGU_UPDATE_PROXY=http://127.0.0.1:7890`（默认仍让 api.github.com 直连，
  不想绕开再加 `CHAOGU_UPDATE_API_BYPASS=0`）；检查失败时会自动改用直连重试一次；
- 更新日志写在 `%APPDATA%\chaogu-picker\updater.log`，排查问题时可以直接看。

几个必须知道的点：

- **便携版（portable exe）不能自我更新**，界面上只会提示去 Release 页下载；
- **开发模式（`npm start`）不检查更新**，只有打包后的安装版才会；
- 发版时 `package.json` 的 `version` 必须递增，否则客户端会认为"已是最新"；`latest.yml` 必须一起上传（管理脚本会自动带上）。
